## Perubahan navigasi

- **Sebelum:** Kompensasi hanya bisa diakses sebagai tab index-3 di `EmployeeDetailScreen`, konten ter-embed langsung (`EmployeeCompensationScreen(employeeId, showTopBar = false)`), tanpa route sendiri di `Routes.kt`/`AppNavGraph.kt`.
- **Sesudah:** Kompensasi punya route sendiri `employees/{employeeId}/compensation`. Tab "Kompensasi" di `EmployeeDetailScreen` kini menampilkan kartu peluncur dengan tombol "Buka Kompensasi" yang memanggil `onOpenCompensation(employeeId)` → `navController.navigate(Routes.employeeCompensation(id))`. Screen baru punya tombol kembali sendiri (`onBack = { navController.popBackStack() }`), sesuai mockup (header dengan tombol kembali + judul + menu tindakan).
- Dikonfirmasi lewat `grep`: hanya satu titik registrasi route Kompensasi (`AppNavGraph.kt`), hanya satu titik pemanggilan `EmployeeCompensationScreen(...)`, dan `EmployeeDetailScreen` memanggilnya lewat `onOpenCompensation`, bukan lagi inline.

## Struktur UI baru (sesuai mockup)

### Header
- `TopAppBar`: tombol kembali (`Icons.Filled.ArrowBack` → `onBack`), judul "Kompensasi", menu tindakan (`Icons.Filled.MoreVert` → `DropdownMenu` dengan item nyata "Info komponen kompensasi" yang membuka dialog info — bukan tombol dekoratif).
- Kartu identitas karyawan (`EmployeeIdentityCard`): nama, status (chip), NIK, posisi + departemen — semua dari `EmployeeProfile` (via `ObserveEmployeeProfileUseCase`, data aktual, bukan dummy).

### 5 tab horizontal (`ScrollableTabRow`, urutan sesuai permintaan)
1. **Ringkasan** — kartu per komponen (GP/TJ/GV/UL-PL/Insentif), status "Belum tersedia" untuk yang tidak ada data, dan catatan eksplisit bahwa Total Kompensasi Bulanan **tidak dihitung** karena TJ/GV/UL-PL belum tersedia (tidak mengarang nilai).
2. **Gaji Pokok** — ringkasan nilai berlaku + riwayat + tombol "+ Tambah" (fungsional, insert nyata ke `EmployeeSalaryHistoryEntity`).
3. **Variable** — 3 kartu (Uang Makan/UM, Uang Transport/UT, Uang Harian/UH), masing-masing status "Belum tersedia", plus kartu formula `GV = (UM + UT + UH) x 25` dengan penjelasan kenapa belum bisa dihitung. Tidak memakai "PH".
4. **Lembur** — 2 kartu (Upah Lembur/UL per jam, Premi Lembur/PL), status "Belum tersedia", dengan catatan eksplisit bahwa tab ini mengatur **tarif/komponen**, bukan mencatat transaksi lembur aktual (pencatatan durasi tetap di halaman Lembur karyawan, tidak dipindah).
5. **Insentif** — daftar + tombol "+ Tambah" (fungsional, insert nyata ke `EmployeeIncentiveEntity`, repository yang sama yang sudah ada — tidak ada mekanisme penyimpanan duplikat).

## Fungsi yang sudah bekerja
- Navigasi penuh: tab "Kompensasi" di `EmployeeDetailScreen` → tombol "Buka Kompensasi" → screen Kompensasi baru dengan 5 tab → tombol kembali → kembali ke `EmployeeDetailScreen`.
- Kelima tab dapat dipilih, menampilkan konten masing-masing, dan `ScrollableTabRow` mendukung scroll horizontal bila label tidak cukup di layar sempit.
- Identitas karyawan (nama/NIK/posisi/departemen/status) ditampilkan dari data aktual (`EmployeeProfile`), bukan dummy.
- Tambah riwayat Gaji Pokok dan tambah Insentif: tervalidasi (`amount > 0`), tersimpan nyata lewat repository yang sudah ada, dikonfirmasi lewat `InfoBanner` setelah sukses, `ErrorBanner` bila gagal.
- Menu tindakan ("Info komponen kompensasi") benar-benar membuka dialog berisi ringkasan status semua komponen — bukan tombol kosong.
- Formula `GV = (UM + UT + UH) x 25` ditampilkan sebagai informasi, tidak dihitung dengan nilai dummy.

## Fitur penyimpanan yang belum tersedia (dan kenapa)
- **TJ, UM, UT, UH, UL, PL per karyawan** — tidak bisa diisi/disimpan. Diverifikasi ulang hari ini terhadap source: `EmployeeEntity`, `EmployeeContractEntity`, `EmployeeSalaryHistoryEntity`, `PositionEntity` tidak punya satu pun kolom untuk nilai-nilai ini (sama seperti temuan `mod-241026-1.md` dan `IMPLEMENTATION_PLAN.md`). Layout kartu untuk komponen-komponen ini **sudah diimplementasikan sesuai mockup** (tab Variable dan Lembur), tapi hanya menampilkan status "Belum tersedia" — tidak ada tombol Simpan yang berpura-pura berfungsi.
- **Kemampuan backend yang dibutuhkan untuk mengaktifkan penyimpanan kelak** (didokumentasikan, bukan diimplementasikan diam-diam):
  - Kolom/tabel baru untuk TJ (tunjangan jabatan, nominal bulanan per karyawan).
  - Kolom/tabel baru untuk UM/UT/UH (nominal harian per karyawan, 3 field terpisah).
  - Kolom/tabel baru untuk UL (nominal per jam) dan PL (nominal premi) sebagai *tarif konfigurasi* per karyawan — berbeda dari `OvertimeRecordEntity.calculationAmount` yang menyimpan hasil transaksi, bukan tarifnya.
  - Semua ini memerlukan migrasi Room (`AppDatabase.kt` version bump + `Migrations.kt`) yang **tidak diajukan atau dijalankan di sesi ini** — sesuai larangan mutlak task ini. Lihat `IMPLEMENTATION_PLAN.md` §5 Proposal 1 untuk detail opsi skema yang sudah dianalisis sebelumnya.
- **Total Kompensasi Bulanan** di tab Ringkasan — sengaja tidak dihitung/ditampilkan karena komponen di atas belum tersedia; ini bukan bug, melainkan larangan eksplisit "jangan mengarang nilai" dari task.
