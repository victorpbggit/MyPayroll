## Ringkasan perubahan per file

### `EmployeeCompensationViewModel.kt`
- `EmployeeCompensationUiState` kini menyertakan `employee: EmployeeEntity?` (sebelumnya tidak ada sama sekali — screen tidak pernah tahu nama/identitas karyawan secara langsung, hanya mengandalkan parent screen) dan computed property `latestSalary`/`employeeNotFound`.
- Constructor menerima `EmployeeRepository` tambahan (selain `EmployeeSalaryHistoryRepository`/`EmployeeIncentiveRepository` yang sudah ada) untuk mengambil data karyawan asli — bukan data dummy.
- `addSalary`/`addIncentive` sekarang memvalidasi `amount > 0L` dengan `require()` sebelum insert (sebelumnya hanya validasi UI `isNotBlank()`, nilai `0` bisa tersimpan), dan mengisi `_infoMessage` setelah `onSuccess` — sebelumnya tidak ada konfirmasi sukses sama sekali, hanya pesan error bila gagal.
- Tidak ada perubahan pada repository/DAO/Entity yang dipanggil — tetap `EmployeeSalaryHistoryRepository`/`EmployeeIncentiveRepository` yang sudah ada.

### `EmployeeCompensationScreen.kt`
- **Header (`CompensationHeader`):** menampilkan nama, status (chip ACTIVE/lainnya), NIK, tanggal bergabung — semua dari `EmployeeEntity` asli yang diterima lewat `employeeId`, bukan data dummy. Menyertakan chip eksplisit "Klasifikasi Manager/Non-Manager: belum tersedia" karena field ini memang tidak ada di `EmployeeEntity` (dikonfirmasi ulang hari ini) — tidak membuat asumsi/nilai default.
- **Ringkasan (`CompensationSummaryCard`):** menampilkan nilai GP terkini (atau "Belum ada data"), dan status chip terpisah untuk TJ/GV/UL-PL/THP Advance — semuanya "belum tersedia". **Tidak ada angka "Total Kompensasi"** dijumlahkan, sesuai larangan di prompt (tidak boleh menampilkan total seolah resmi padahal sumbernya belum lengkap).
- **Gaji Pokok (GP):** fungsional penuh, dari `EmployeeSalaryHistoryRepository` — kartu nilai saat ini (nominal + satuan periode Bulanan/Harian/Per Jam dari `SalaryType`) + riwayat lengkap + tombol "Tambah" yang membuka dialog nyata (`AddSalaryDialog`, pakai `RupiahMoneyField` dengan validasi `amount > 0`).
- **Tunjangan Jabatan (TJ), Gaji Variable (UM/UT/UH), Kompensasi Lembur (UL/PL):** masing-masing satu kartu status (`UnavailableComponentCard`) berisi chip "Belum tersedia" + daftar sub-komponen + penjelasan spesifik kenapa (tidak ada kolom di schema untuk TJ/GV; untuk UL/PL dijelaskan secara presisi bahwa *Payroll Setup* punya pengaturan persentase/nominal tapi itu **global**, bukan tarif per karyawan). **Tidak ada tombol Simpan/Edit apa pun di kartu-kartu ini** — sesuai larangan membuat tombol yang terlihat berfungsi tapi tidak melakukan apa-apa.
- **Insentif:** fungsional penuh, dari `EmployeeIncentiveRepository` — daftar + tombol "Tambah" yang membuka dialog nyata (`AddIncentiveDialog`, `RupiahMoneyField` + validasi).
- **THP Advance:** satu kartu status "belum tersedia" (tidak ada entity/alur deklarasi-realisasi di codebase, dikonfirmasi lewat `IMPLEMENTATION_PLAN.md`/audit 23-10).
- Nama "PH" tidak dipakai di mana pun pada UI ini — kelompok ketiga ditulis "Gaji Variable (GV)" dengan sub-label UM/UT/UH sesuai instruksi (PH sudah dipensiunkan).
- Struktur tab (`TabRow` + FAB tunggal yang perilakunya tergantung tab tersembunyi) dihapus, diganti satu `LazyColumn` terstruktur per kelompok dengan tombol "Tambah" yang jelas terikat ke section masing-masing (GP dan Insentif) — mengurangi ambiguitas "tombol ini untuk apa".
- `ErrorBanner` (sudah ada) dan `InfoBanner` (baru) ditampilkan sebagai item di dalam alur scroll, bisa ditutup (`onDismiss` memanggil `viewModel::clearMessages`).
- Loading state (`LoadingState`) dan empty state (karyawan tidak ditemukan / riwayat gaji kosong / insentif kosong) ditangani eksplisit, bukan diam-diam menampilkan layar kosong.

### `CommonComponents.kt`
- Ditambah `InfoBanner(message, onDismiss, modifier)` — pasangan positif dari `ErrorBanner` yang sudah ada, dipakai untuk konfirmasi "berhasil disimpan". Tidak ada composable lain yang diubah.

## Perilaku UI sebelum vs. sesudah

| Aspek | Sebelum | Sesudah |
|---|---|---|
| Identitas karyawan di screen Kompensasi | Tidak ditampilkan sendiri (hanya lewat top bar `EmployeeDetailScreen`, `showTopBar=false` di sini) | Kartu header sendiri: nama, status, NIK, tanggal bergabung, status klasifikasi |
| Struktur | 2 tab datar (Gaji/Insentif), FAB tunggal yang artinya berubah sesuai tab aktif | 1 halaman scroll, 6 kelompok komponen berurutan, tombol "Tambah" per section yang jelas |
| TJ/GV/UL/PL/THP Advance | Tidak disebutkan sama sekali di UI (seolah tidak ada) | Masing-masing kartu status eksplisit "Belum tersedia" + alasan spesifik |
| Total kompensasi | Tidak ada (tidak berubah) | Tetap tidak ada — secara eksplisit dijelaskan di UI kenapa tidak dihitung |
| Konfirmasi simpan berhasil | Tidak ada (dialog langsung tertutup, tidak ada tanda sukses) | `InfoBanner` muncul setelah insert benar-benar sukses |
| Validasi nominal | Hanya `isNotBlank()`, nominal `0` bisa tersimpan | `amount > 0` divalidasi di ViewModel (`require`) sebelum insert, dan di UI (tombol Simpan nonaktif + `supportingText`) |
| Satuan periode GP | Ditampilkan sebagai `item.salaryType.name` mentah (`MONTHLY`) | Label Indonesia ("Per bulan"/"Per hari"/"Per jam") lewat `periodLabel()` |

## Fungsi yang sudah bekerja
- Menambah riwayat Gaji Pokok (insert ke `EmployeeSalaryHistoryEntity` lewat repository yang sudah ada) — tervalidasi, terkonfirmasi lewat `InfoBanner`.
- Menambah Insentif (insert ke `EmployeeIncentiveEntity` lewat repository yang sudah ada) — tervalidasi, terkonfirmasi lewat `InfoBanner`.
- Header identitas karyawan menggunakan data `EmployeeEntity` asli berdasarkan `employeeId` yang diterima dari navigasi tab `EmployeeDetailScreen`.
- Loading state, empty state (riwayat gaji/insentif kosong, karyawan tidak ditemukan), dan error state (gagal simpan) semua tersambung ke kondisi nyata, bukan statis/dummy.
- Navigasi: tab "Kompensasi" (index 3) di `EmployeeDetailScreen` tetap memanggil `EmployeeCompensationScreen(employeeId, showTopBar = false)` tanpa perubahan pada `AppNavGraph.kt`/`Routes.kt` — route/entry point tidak disentuh dan tetap berfungsi.

Alasan: `EmployeeEntity`, `EmployeeContractEntity`, `EmployeeSalaryHistoryEntity`, `PositionEntity` (dibaca ulang hari ini) tidak punya satu pun kolom untuk nilai-nilai ini sejak `PayComponentEntity` dihapus 13-10-2026; task ini melarang perubahan `data.local.dao`/`data.local.entity`.
